# 아침 브리핑

오늘 업무를 시작하기 전에 확인할 정보를 4개 섹션으로 정리해 주세요. **메인 세션에서 4개 도구를 한 응답에 병렬 호출**합니다 (한 assistant 턴에 tool_use 4개).

## 사전 조건

1. `config.local.md`를 읽어 사용자 프로필·관심 통화쌍을 확보합니다. 파일이 없으면 "먼저 `config.example.md`를 `config.local.md`로 복사해 채워 주세요"라고 알리고 중단합니다.

## 수행 단계

### 1) 병렬 조회 (한 응답에 동시에)

| 섹션 | 도구 | 인자 |
|---|---|---|
| 메일 | Gmail `search_threads` | `query: "is:unread newer_than:1d"`, `pageSize: 30` |
| 일정 | Calendar `list_events` | `calendarId: <기본 캘린더 ID>`, `startTime: 오늘 00:00 KST`, `endTime: 오늘 23:59 KST`, `timeZone: Asia/Seoul`, `orderBy: startTime` |
| 뉴스 | ItNewsSearch `News_Article` | `query: <블로그 주제 키워드 중 하나, 기본 "AI 자동화">` |
| 환율 | Eodi `get_exchange_rates` | 관심 통화쌍별로 1회씩 (USD/KRW, JPY/KRW, EUR/KRW 등) — **이것도 같은 응답에 같이 띄움** |

> 메인 세션은 한 assistant 턴 안에 tool_use 블록을 여러 개 두어 **모든 호출을 동시에** 실행합니다.

### 2) 메일 분류 후처리

`search_threads` 결과에서 발신자 도메인·제목으로 다음 4개 버킷 중 하나로 분류:

- 🔴 중요: 화이트리스트 일치 또는 명백한 업무 메일
- 🟡 확인: 청구서·일정 안내 등
- 🟢 뉴스레터/광고
- ⚪️ 스팸·만료 OTP 등 무시 후보

Top 5만 표로 표시. 화이트리스트가 비어 있으면 발신자 도메인 평판으로 추정.

### 3) 집중 시간 계산

오늘 일정이 있으면 업무 시간(09:00–18:00) 내 **빈 구간이 사용자 최소 단위(분) 이상**인 블록만 추천. 일정이 없으면 "오늘 일정 없음 — 09:00–18:00 전체 비어 있음".

### 4) 팬인 — 결과 합치기

아래 포맷으로 한 장의 마크다운 조립.

## 출력 포맷

```markdown
# 아침 브리핑 (YYYY-MM-DD)

## 📧 중요 메일
| 발신자 | 제목 | 분류 |
|---|---|---|
...

## 📅 오늘 일정 + 집중 시간
- HH:MM–HH:MM 이벤트 (장소)
**집중 시간 추천**:
- HH:MM–HH:MM (N분) — 비어 있음

## 📰 뉴스 3건
1. [제목](링크) — 한 줄 요약
2. ...
3. ...

## 💱 환율 (출처·기준일)
| 통화쌍 | 현재가 | 비고 |
|---|---|---|
```

## 실패 처리

- 한 도구가 에러를 반환해도 다른 섹션은 정상 출력. 실패한 섹션은 `❌ <도구명> 실패: (원인)`로 표시.
- `config.local.md`에 필수 필드(관심 통화쌍 등)가 비어 있으면 해당 섹션만 "설정 필요"로 스킵.

## 참고

- **서브에이전트 호출은 사용하지 않습니다.** 이 환경에서 Agent 도구로 스폰된 서브에이전트는 MCP 서버 접근 권한이 분리되어 있습니다. 단순 fetch-and-return 패턴은 메인 세션 병렬 호출이 동일 속도이고 항상 작동합니다.
- **SDK 경로(`scheduled/daily-brief.ts`)** 는 별도 프로세스로 `runSpecialist()`를 통해 페르소나 파일(`.claude/agents/`)을 그대로 활용합니다. 그쪽은 손대지 않습니다.
