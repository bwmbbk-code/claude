# 아침 브리핑 (멀티 에이전트)

오늘 업무를 시작하기 전에 확인할 정보를 5개 섹션으로 정리해 주세요. **도메인별 서브에이전트 3명을 병렬로 호출**해 결과를 수합합니다.

## 사전 조건

1. `config.local.md`를 읽어 사용자 프로필·관심 종목·관심 코인·관심 통화쌍을 확보합니다. 파일이 없으면 "먼저 `config.example.md`를 `config.local.md`로 복사해 채워 주세요"라고 알리고 중단합니다.

## 수행 단계

### 1) 팬아웃 — 3개 서브에이전트를 **한 메시지 안에서 동시에** 호출

Task 도구를 사용해 다음 세 에이전트를 **병렬**로 소환합니다 (한 assistant 턴에 tool_use 3개).

| 서브에이전트 | 지시 요약 |
|---|---|
| `mail-analyst` | "최근 24시간 미읽음 스레드에서 중요도 Top 5를 표로 리턴. 분류 이모지 포함." |
| `calendar-planner` | "오늘 일정 목록 + 업무 시간 내 집중 시간 블록 추천." |
| `finance-researcher` | "`config.local.md`의 관심 통화쌍·관심 종목·관심 코인 현재가/전일대비를 두 개 표로 리턴." |

### 2) 추가 조회 (메인 세션에서 직접)

- **뉴스 3건**: ItNewsSearch `News_Article`로 최신 IT 뉴스 3건. 짧아서 에이전트까지 분할할 필요 없음.

### 3) 팬인 — 결과 합치기

세 에이전트의 리턴 + 뉴스 결과를 아래 포맷으로 한 장의 마크다운에 조립합니다. 각 에이전트 출력은 섹션 본문에 그대로 **인라인**하되 중복 제목은 제거.

## 출력 포맷

```markdown
# 아침 브리핑 (YYYY-MM-DD)

## 📧 중요 메일
<mail-analyst 표 그대로>

## 📅 오늘 일정 + 집중 시간
<calendar-planner 출력 그대로>

## 📰 뉴스 3건
1. [제목](링크) — 한 줄 요약
2. ...
3. ...

## 💱 환율 · 📈 시장
<finance-researcher 두 표 그대로>
```

## 실패 처리

- 서브에이전트 한 명이 에러를 반환해도 다른 섹션은 정상 출력. 실패한 섹션은 `❌ <에이전트명> 실패: (원인)`으로 표시.
- `config.local.md`에 필수 필드가 비어 있으면 해당 섹션만 "설정 필요"로 스킵.
